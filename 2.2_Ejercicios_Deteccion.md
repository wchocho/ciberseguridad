# 2.2 Ejercicios y Práctica: Protección y Detección

## Sección A: Preguntas de Reflexión y Debate

1. Un estudiante dice: *"Mi computadora Windows ya viene con el Firewall activado, así que no entiendo por qué la UTU además compra un IPS (Sistema de Prevención de Intrusos) costosísimo para la red"*. Explica técnicamente la diferencia entre lo que hace el Firewall en la PC y el IPS en la red.
2. Si un SIEM recibe 10.000 logs de "Contraseña Incorrecta" en un minuto, pero luego recibe 1 log de "Login Exitoso" para el mismo usuario. ¿Por qué esta correlación específica es la alarma más grave (Prioridad 1) para un SOC?
3. En el caso WannaCry, una sola falla de *Patch Management* provocó un colapso global. Teniendo en cuenta que instalar parches a veces "rompe" aplicaciones viejas en las empresas, ¿cómo diseñarías una política de actualizaciones para un Hospital que mantenga un equilibrio entre Disponibilidad y Seguridad?

## Sección B: Role-Play / Arquitectura de un Playbook SOAR

**Escenario:**
Eres el Ingeniero de Automatización SOAR del Banco Central. 
Tienen un problema: los empleados reportan 50 correos de *Phishing* sospechosos por día reenviándolos a `seguridad@banco.com`. Los 3 analistas humanos del SOC están agotados porque cada investigación manual lleva 20 minutos (tomar la URL sospechosa, buscarla en herramientas externas, y borrar el correo si es malo).

**Tu Tarea:**
Diseña la lógica de un **Playbook SOAR** (un flujo automatizado paso a paso) que se ejecute cada vez que un correo llega a `seguridad@banco.com`. Define claramente:
* El *Trigger* (El disparador).
* Dos integraciones automáticas (Ej: extraer URL, consultar API de "VirusTotal").
* Las condiciones (SI es malo -> HACER X ; SI es bueno -> HACER Y).

## Sección C: Micro-Laboratorio de Reglas NIDS (Snort)

Eres un analista revisando la configuración del IPS de código abierto (Snort) de la empresa.
Encuentras esta regla activa en el sistema:

```text
alert tcp $EXTERNAL_NET any -> $HTTP_SERVERS $HTTP_PORTS (msg:"Posible Ataque XSS"; flow:to_server,established; content:"<script>"; http_client_body; sid:10005;)
```

**Instrucción:**
Desglosa técnicamente qué está haciendo esta regla:
1. ¿Qué acción toma cuando detecta el ataque: ¿bloquea el tráfico (`drop`) o solo avisa (`alert`)?
2. ¿Hacia qué dirección va el tráfico? (De dónde a dónde).
3. ¿Qué palabra exacta (`content`) está buscando dentro del paquete para considerar que es un ataque de inyección web?
